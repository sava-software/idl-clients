# Fuzz seed corpora

Seed provenance lives here — next to, never inside, a corpus directory, where a
file would itself be fed to the harness as a seed. The replay test that runs
every seed inside `check` is generated by the sava-build hardening plugin
(`<Harness>SeedReplayTest`, one per target); each harness's contract is
documented on the harness class itself.

A corpus does two independent jobs. A **bootstrap** corpus buys coverage a
mutator would take too long to reach alone; a **regression** corpus is where a
finding lands, so a fixed crash stays fixed. "Every prefix of this format is
valid" answers only the first — every target here carries a corpus, and the
sections below say which job each one is doing.

## `scopeReader/`

The fixed 29704-byte `OracleMappings` layout is unreachable from a scratch
mutator, so every seed is either a real account or a minimized finding:

- `4zh6bmb77qX2CL7t5AJYCqa6YqFafbz3QJNeFvZjLowg`, `Chpu5ZgfWX5ZzVpUx9Xvv4WPM75Xd7zPJNDPsFnCpLpk`
  — real mainnet OracleMappings account dumps (file name = account address),
  fetched 2026-07-16. These carry the live oracle-type/refPrice index graph the
  parser's recursion walks.
- `slow-exp-95f9f30f`, `slow-exp-aa041616` — minimized hostile `FixedPrice`
  exponent inputs that drove ~50s parses (`BigDecimal.movePointLeft` inflating a
  very negative scale into a billion-digit `BigInteger`). Fixed by
  `scaleByPowerOfTen` plus Pyth exponent range checks; also pinned by
  `ScopeReaderHostileInputTests`.

## `jupiterResponse/`

The harness reads `data[0]` as a parser selector and the rest as the JSON
body, so every seed leads with its selector byte. Each seed is the test-fixture
body for one parser family (quote, full swap-instructions response with a
present cleanup, the two field-scan orderings, the swap-ix wrapper, swap-tx,
ultra order, price/token maps, the ASR claim envelope, and the request
records), assembled 2026-07-23 from the fixtures in
`JupiterSwapApiClientTests` / `JupiterSwapInstructionsTests` /
`ClaimProofTests` — structured JSON is slow to reach from a scratch mutator.

## `dlmmPrice/`

- `trunc-envelope-step511-id353`, `trunc-envelope-step8129-id36` — minimized
  findings from the harness's original fixed `1e-12` tolerance. Not code
  defects: at exponent budgets near 20 the Q64.64 `pow`'s inverted-fraction
  intermediates shrink and per-step truncation legitimately costs
  `~e^budget * 2^-64` relative (2e-12 and 1.7e-11 here, bit-for-bit the Rust
  reference's own answers). The harness bound is budget-scaled accordingly;
  the exact values and both sides of the envelope are pinned by
  `DlmmUtilsTests.truncationEnvelopeAtHighExponentBudgets`.

## `routeV2/`

The harness writes the discriminator itself: `data[0]` selects the variant (odd
-> `sharedAccountsRouteV2`) and the rest is the payload after it. The `Swap`
enum has ~150 ordinals, most of them carrying their own fields, so a route plan
that parses is slow to reach from scratch — these are bootstraps as well as
regression slots. The three real payloads were taken 2026-07-25 from successful
mainnet transactions to `JUP6LkbZbjS1jKKwapdHNy74zcZ3tLUZoi5QNyVTaV4`:

- `single-step-unit-swap` — `PumpSwapBuyV3` (ordinal 99, a unit variant),
  1500 bps slippage, no platform fee.
- `single-step-parameterized-swap` — `Riptide` (ordinal 127), whose variant
  carries its own byte, plus a 35 bps platform fee.
- `shared-accounts-route` — `GoonFiV3` (ordinal 151, also parameterized) re-led
  with the odd selector and the `u8 id` that is the shared layout's only
  difference from the plain one.
- `two-step-split-plan` — synthesized from a real header: two real ordinals
  (`PumpSwapSellV3WithCashbackClaim` 148, `PumpSwapBuyV3` 99) at 5000 bps each,
  with chained input/output indexes. Live routes sampled here are all single
  hop, so the multi-step vector exists in no real payload.
- `invalid-defi-tuna-option-tag`, `unknown-bison-fi-predict-side`,
  `unknown-whale-street-v2-side` — minimized `fuzzAll` / `fuzzRouteV2` findings
  from 2026-08-27. The first carries an invalid option-presence tag, which is a
  normal RuntimeException rejection; the others carry unknown nested enum ordinals
  that `SerDeUtil.read` deliberately represents as null and the harness now rejects
  before generated serialization. `RouteV2DataTests` pins every rejection path by
  name.

## `orcaTickMath/`

Every prefix is a valid sqrt price (the harness folds the bytes into the domain
modulo its range), so these are regression slots that also park the fuzzer on
the boundaries the approximation is most likely to mis-bracket:

- `min-sqrt-price`, `max-sqrt-price` — the exact domain endpoints
  (`MIN_SQRT_PRICE_X64` / `MAX_SQRT_PRICE_X64`), reached by seeding the fold
  with the range and range-1.
- `tick-zero` — exactly `2^64`, the Q64.64 representation of tick 0.
- `non-positive-guard` — a leading zero byte, which routes to the guard branch
  that must reject a non-positive price instead of computing a tick from it.

## `whirlpoolQuote/`

A fixed 64-byte tuple, all of it valid, so again regression slots plus the
position shapes worth keeping in front of the quote math:

- `full-range-both-transfer-fees` — full-range position at tick 0 with both
  Token-2022 transfer fees present.
- `u128-liquidity-max` — liquidity `2^128 - 1` with maximum slippage, which
  drives the u64 conversion guards.
- `zero-liquidity-equal-ticks` — the degenerate position (zero liquidity,
  lower tick == upper tick) at zero slippage.
- `price-below-range`, `price-above-range` — the two single-sided branches,
  with the price pinned to the exact domain endpoints.
